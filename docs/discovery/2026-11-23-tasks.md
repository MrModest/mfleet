# Tasks shared between agents and humans

Captured: 2026-11-23

## Desired outcome

Agents can add, update, delete, and check tasks through the CLI, and can
tell the user what they are waiting for.

## Ideas

A `mfleet tasks` subcommand.

Tasks are not bound to the session that created them, so agents can pick
them up and work on them in parallel. The current session ID only records
who created the task. (agent-fleet's tasks are fleet-wide too.)

Task shape sketch:

```ts
type TaskCreator = {
  host: string;
  harness: "codex" | "claude" | "pi";
  sessionId: UUID;
};

type Task = {
  kind: "agent" | "human";
  createdBy: TaskCreator;
  parent?: TaskId;        // parent task
  children: TaskId[];     // child tasks
  status: "new" | "in-progress" | "blocked" | "done" | "cancelled";
  blockedBy: TaskId[];    // other tasks' IDs
};
```

Most tasks are `agent` tasks. When an agent is blocked by something only a
human can do, it creates a `human` task and is blocked by it. The agent
still tracks it:

1. The human asks the agent "what is blocking you?"
2. The agent fetches the task and answers "I'm waiting for you to do this
   and this".
3. The human does it and tells the agent "I've done this and this".
4. The agent marks the `human` task `done` and is unblocked.
